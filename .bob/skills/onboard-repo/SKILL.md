# onboard-repo skill

Use this skill when someone says "onboard me to this repo" or similar.

## Steps

### Step 1 — Run the deterministic pipeline

```bash
devpilot scan <repo>
devpilot verify <repo>
```

Both commands write their output to `<repo>/.devpilot/`. If they are already present and
recent (< 24 hours old), you may skip re-running.

### Step 2 — Identify top-level modules

Read `<repo>/.devpilot/facts.json`. Extract the list of top-level modules:
- For Python repos: directories under the repo root that contain `__init__.py`, or top-level
  `.py` files with more than 20 LOC (excluding test files and config).
- For JS/TS repos: directories listed in `facts.entrypoints` or top-level `src/` subdirs.

### Step 3 — Spawn one explore subagent per module (IN PARALLEL)

For each module identified in Step 2, spawn an `explore` subagent with this brief:

> Explore the module at `<module_path>` in the repository at `<repo>`. Return:
> 1. **Purpose** — what this module does in 2–3 sentences
> 2. **Key files** — the 3–5 most important files with `file:line` citations
> 3. **Public entry points** — functions, classes, or CLI commands that callers use
> 4. **Connections** — which other modules import from or are imported by this one
> 5. **Gotchas** — anything in `facts.json` todos or findings related to this module
>
> All claims must cite a `file:line`. Do not invent information not found in the code.

Wait for all subagents to complete before proceeding.

### Step 4 — Merge into ONBOARDING.md

Write (or overwrite) `<repo>/ONBOARDING.md` with this structure. All commands must come
from `verify.json` (passed steps only). All env vars must come from `facts.json`. All owners
must come from `facts.json`.

```markdown
# ONBOARDING.md — <repo name>

> Generated by DevPilot. Every command is verified; every fact is cited.
> Report: [report.html](.devpilot/report.html)

## Overview
<2–3 sentence summary of what the project does, grounded in README and entrypoints>

## Architecture
<Mermaid diagram or prose description of module relationships from Step 3>

## Setup
<Numbered list of commands from verify.json where passed=true, with durations>

## Environment Variables
<Table: Name | Read At | Documented In — from facts.json env_vars>

## Drift Warnings
<Table of findings from findings.json — anything high/medium severity first>

## Module Guide
<One section per module from Step 3 subagent results>

## Who to Ask
<Table from facts.json owners — Path | Owners | Source>

## First 5 Tasks
<From report first_tasks ranking — file:line, reason>

## Glossary
<Key domain terms found in the README/docs, defined in 1 sentence each>
```

### Step 5 — Generate and link the HTML report

```bash
devpilot report <repo>
```

Confirm `<repo>/.devpilot/report.html` was produced. The link at the top of `ONBOARDING.md`
should point to it.

## Done check

- [ ] `<repo>/ONBOARDING.md` exists with all nine sections
- [ ] Every command in Setup section has a `verify.json` passing entry
- [ ] No uncited commands, paths, env vars, or owners
- [ ] `<repo>/.devpilot/report.html` exists and is linked
